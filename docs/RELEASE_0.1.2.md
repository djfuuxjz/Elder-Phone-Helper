# V0.1.2 模型引导与请求机制调整

日期：2026-10-19。APK：`dist/phone-assistant-0.1.2-debug.apk`；versionCode 3。包名、签名与 V0.1.1 相同，可覆盖安装。
SHA-256：`2950612074cb973cf38542bc7cb0af5bb0d9a2aaed5239ed119383b1bbec6bde`。

## 本次按用户要求调整

1. **删除 App 固定联系人校验。** 不再要求节点/证据精确等于“女儿”，联系人由模型结合完整备注和当前页面判断。模型提示词不再强制把实际备注改成“女儿”。
2. **删除 confidence 数值硬门槛。** 数值仍记录为参考，App 不再因低于 0.80/0.90 拒绝；合法 JSON、字段类型、坐标、页面有效性仍检查。任务完成仍需呼叫状态证据，联系人页/菜单不算成功。
3. **兼容 evidence。** 数组和模型返回的一段文字均可解析并保留，不再把文字证据静默变为空。
4. **直接打开微信。** 从助手启动任务时使用 Android 应用启动接口。已在微信则继续观察；停留在任意桌面页时直接请求打开微信，无需找图标。启动失败会记录原因并提示手动打开后重试。不自动点击、滑动或输入微信页面。Debug 等待起点模式仍先等待测试者确认。
5. **明确取消原因。** 新日志 `request_cancelled_by_app` 记录请求 ID 与页面变化、页面不可读、重试、停止、服务中断等原因。失败响应的 error 为可读原因，同时保留 exception_type、exception_message、error_code、cancel_reason。没有取消记录的网络错误不会被猜测成页面变化。
6. **任务过程摘要。** 每次输入携带本任务最近最多 40 条摘要，每条最多 400 字符，包含可见页面变化、模型判断、已展示但尚未确认执行的建议、拒绝/失败、取消和用户重试。新任务清空历史；不是用户历史记录产品。模型被明确要求参考失败原因调整方案。不能保证模型绝不重复，需要真机数据验证。
7. **发送间隔至少 1 秒。** 进程内共享发送控制覆盖正常请求、截图补充、重试及新会话。等待在后台执行，不阻塞界面；等待期间取消不发送。以实际网络调用开始记录计算，不按按钮点击或准备时间计算。
8. **日志查看器同步更新。** 主动取消单独显示，错误响应不再一律标为“模型返回”。旧日志没有记录的具体原因不会凭空补出。

## 安装后复验

1. 覆盖安装后启动任务，检查能从助手直接打开微信；再从没有微信图标的桌面页测试。
2. 使用实际完整备注“艾子翔女儿”执行任务，检查不再出现 App 的固定姓名拒绝。
3. 请求中切页/点击重试/停止，各导出一次新日志，检查具体取消原因与对应 request_id。
4. 查看下一次 request.input 的 step_context，确认有上一步建议、失败或重试摘要；已展示不标为已成功执行。
5. 查看相邻 request 时间戳间隔，不应小于 1000 ms（设备墙上时间变化另看实际单调时钟测试）。
6. 拖动浮层、停止返回助手和任务完成状态按旧版继续回归。

本次没有连接小米 15，也没有使用真实 API 凭据运行新版本；系统是否允许从无障碍服务直接打开微信、实际模型效果与微信各页面仍待用户实测。旧版日志不是新版已通过真机验收的证据。
