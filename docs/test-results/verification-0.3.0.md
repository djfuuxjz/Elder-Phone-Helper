## 新增重点用例

- 用户给定的 1200×2670、空 target_node、有效坐标样例通过。
- 空白 target_node 兼容，字面字符串 null、旧/未知节点拒绝；其他必填字段仍严格校验。
- 越界、节点/框冲突、区域过大拒绝，具体规则和实际值保留。
- 600 个空容器后的按钮保留；700 个有效节点预算优先保留交互控件；截断统计可追踪。
- 截图权限失败保留具体原因；图片/快照/请求元数据关联；文本模型不需要发送图片。
- 人工模式只展示建议，不自动点击；系统已验证时不走 GUI，未验证时按开关/唯一图标/一次尝试的规则降级。
- 输入事件不保存验证码内容，系统事件不确定来源时不归因为确定用户。
- 没有当前完成证据时不进入完成态；复合目标不会只因打开应用本地成功。
- 异步证据仍有排队任务时阻止导出/清理，队列清空后解除。

## 复现

需要 JDK17、SDK35/Build Tools35.0.0，配置 SDK 路径后：

```sh
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
node --test 日志查看器/tests/test-geometry.cjs
node 日志查看器/tests/test-integration.cjs
```

浏览器集成测试使用 Node22 内置 WebSocket 和 Mac 默认 Chrome 安装位置，在独立临时浏览器资料目录运行，测试图片为合成样例，不使用用户的私密截图。

`test-core.cjs` 中的既有真机样本回归需设置 LOG_FIXTURE 为本机的 `run_1792305039224_bd125093/events.jsonl`；该私密日志未放入源码包。测试输出仅报告数量和断言结果。

构建工具在临时目录准备，没有改动原工程的本机 SDK 配置，也没有把 JDK/SDK、调试私钥或真实运行日志加入源码包。新 APK 与 V0.2.0 的证书不同，签名问题和手机验收步骤见 RELEASE_0.3.0.md。
