# 当前数据契约

依据 V0.3.0 源码，2026-11-05。旧版字段可能缺失，不补造；旧 prompt_version 不等于 App 版本。

## 任务与观察

TaskGoal 保存本次 goal、fixed 和 task key。自定义目标贯穿请求与日志；模板不能覆盖目标。默认快捷任务兼容原 task key。

Snapshot JSON 包含 snapshot_id、package_name、window_id、screen_width、screen_height、captured_at、truncated、collection、nodes。captured_at 使用单调时钟，节点 ID 只在该快照有效。

节点包含 id、resource_id、text、description、kind、clickable、editable、focused、hint、bounds。bounds 为原始全屏像素 [left,top,right,bottom]；可编辑值/密码文本不写入树。

collection 记录 visited、collected、meaningful_candidates、empty_containers_skipped、traversal_limit=3000、node_limit=700、depth_limit=50、truncation_reasons。截图记录原始尺寸、屏幕尺寸、旋转和 coordinate_transform。通过前后树和事件版本检查一致性，不承诺原子采集。

## 模型输入输出

输入携带 goal、session_id、step、attempt、snapshot、step_context、workflow、launchable_apps、capture_info。图片仅在配置支持时放入请求；日志请求体以 local:附件引用替代 Base64。

输出字段 current_state、next_action、target_node、target_bbox、instruction、confidence、task_completed、evidence；open_app 还需 target_app。

| 规则 | 当前行为 |
|---|---|
| 动作 | click/back/scroll/input/wait/complete/blocked/need_screenshot/open_app |
| 空节点 | JSON null；兼容空字符串和纯空白。字面“null”不归空 |
| 点击目标 | 有效当前节点或有效 bbox；同时提供时需重叠；区域小于屏幕 60% |
| 坐标 | 四个整数、正面积、落在当前屏幕内；不存在节点仍拒绝 |
| confidence | 数字且 0..1，不作接受阈值 |
| 完成 | complete 与 true 一致；控制器另检查当前证据；精确打开目标有独立本地验证 |

## 事件与关联

每条事件含 timestamp、session_id、time_zone、task_key、goal、event、data。timestamp 为记录的墙钟时间；耗时与 system_event_time_ms 等使用单调时钟，不能直接和墙钟相减。

data 按事件包含 step、attempt、request_id、snapshot_id、ui_tree_ref、screenshot_ref。step 不严格等于一次物理操作；重试、观察和验证也可推进步骤，同一页面请求重试递增 attempt。会话、请求、快照应一起关联，不能仅凭 step 跨会话拼接。

| 事件 | 含义 |
|---|---|
| capture_started / snapshot_saved / capture_error | 开始采集、证据保存、明确采集失败 |
| request_prepared | 材料已准备，不计实际调用 |
| request | 网络执行开始，计调用；排队等待单独记录 |
| request_body_sent | 请求正文上传结束；不代表服务已处理或目标完成 |
| request_prepare_error | 发送前准备失败，不等同主动取消 |
| response / decision / invalid_decision | API 返回、模型建议、解析或目标规则拒绝 |
| discarded / request_cancelled / request_cancelled_by_app | 过期结果、发送前取消、App 主动取消，分开呈现 |
| guidance | 已展示人工指引，executed=false |
| execution_requested / execution_result / execution_verification | 执行方式和派发结果、后续页面验证；派发不等于任务成功 |
| behavior_observed / behavior_page_link | 系统实际报告事件及前后页面关联；不保证用户来源 |
| completed_evidence / success_displayed / end | 完成证据、提示展示、运行终态 |

screenshot_saved 与 screenshot_sent_to_model 分别表达本地保存与实际上传，不能互相推断。截图失败填缺失原因，不伪造附件。

失败使用 stage、error_code、rule、expected、actual、error，并保留相关模型内容、请求和附件引用。例：MISSING_CLICK_TARGET、BBOX_OUT_OF_BOUNDS、NODE_BBOX_MISMATCH、TARGET_TOO_LARGE、SNAPSHOT_CHANGED、APP_CANCELLED、NO_ACCESSIBLE_ROOT。旧日志只有 error 时显示其原文，不补造错误码。

## 行为、计时与复盘

系统事件记录类型、时间、应用、可匹配节点/区域及来源。actor_certain=false 时不得写成确定人工操作。自动派发另有 execution 事件，输入事件不保存 text/beforeText 或输入值；去重只聚合短时间重复事件。

measurement_start 从首份有效稳定观察开始计任务时长，准备起点不计入。稳定等待、截图、排队、请求耗时分别记录；page_first_seen_at_ms 是程序首次看到候选页，非物理画面达成精确时刻。完成确认与提示字段用于诊断，不凭配置推算真实提速。

成功复盘是额外模型调用，purpose=workflow_review，计入总调用并可分别统计。当前仅固定任务参与；新任务/停止可取消旧复盘。异步证据未保存完时不允许导出/清理。旧日志和发布快照不因契约更新而重写。
