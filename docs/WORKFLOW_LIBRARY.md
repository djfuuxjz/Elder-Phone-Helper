# 可复用流程库（V0.1.3）

用途：把成功经验和开发人员编写的流程放进后续模型请求。仅支持当前“给女儿打视频电话”任务，不增加老人端任务入口、不自动操作微信。

## 执行

默认路线：打开微信 → 搜索 → 输入女儿 → 根据备注与上下文选择联系人 → 聊天页输入栏旁加号 → 音视频通话 → 视频通话 → 确认呼叫状态。
从聊天页等中间起点开始时，依据当前页面跳过之前步骤，不强制从头走。
每次请求带上当前选定流程版本、阶段、当前搜索/输入/加号节点，以及原有步骤摘要。流程只保存语义，不缓存屏幕坐标。
联系人仍由模型结合实际备注判断，没有恢复精确姓名或 confidence 阈值拦截。

## 搜索与纠偏

读屏增加 editable、focused、hint。输入步骤使用当前真实 EditText/可编辑节点并高亮；多个输入框且没有明确目标时不猜测。
搜索定位优先真实标注为搜索的控件，拒绝把空白横条当搜索框。聊天页误选更多信息时，如可唯一识别输入栏旁加号，则纠正坐标和提示文字，并记录 grounding_corrected。
启用流程时，联系人检索阶段不接受逐屏滑动建议；其他页面要求模型尽量少滑动。控件不可识别时请求补充信息或暂停，不套用固定坐标。具体微信版本的控件仍需真机验证。

## 成功与学习

完成不以“已展示视频通话指引”代替真实呼叫。模型完成判断需页面呼叫证据；同时，在已展示视频呼叫指引后，稳定页面出现等待/呼叫状态、视频/摄像头控件和挂断/取消控件，可由本地识别直接终止任务。
任务进入 COMPLETED 后，旧请求失效、停止轮询，悬浮窗显示“任务已成功”1秒后关闭。新的任务或主动停止会撤销旧计时器。
成功后另发一次云端复盘请求，也遵守至少1秒发送间隔。复盘使用本次步骤轨迹、失败建议和成功证据，要求删去绕路、重复和错误，输出证据支持的较优路线。未实测的新捷径必须标为待验证，不能声称已经验证或全局最优。
复盘失败不会撤销任务成功，也不会再次引导；错误保存在 Debug。模型候选保存来源运行、基础版本、理由和独立版本编号，始终不覆盖人工/已启用版本。
新任务或服务断开会取消仍在进行的复盘。没有成功证据的任务不会生成成功经验。

## 开发维护

“我的 → 流程库 · 开发维护”：
- 查看所有版本、来源、锁定状态、当前启用版本、复盘理由和原版本对照。
- 新建或粘贴 JSON 导入；编辑后生成新候选，原版永久保留。
- 下次任务试运行某版本，不改变默认启用版本；也可以取消试运行。
- 真机确认后启用，或回退到任一保留版本；也可停用流程约束。
- 锁定/解锁人工维护版本。锁定版本不能修改，模型复盘只会创建新候选。
- 导出 JSON，后续可在新建页面粘贴导入。

格式：name（名称）、task_key（video_call_daughter）、steps（1—20 条语义步骤，每条1—500字符）。文件原子保存于 App 私有存储，不上传流程库全量数据；只把当前选定版本发给模型。
流程状态中的“候选/保留”不是已验证标记。试运行与人工验收记录保存在运行日志中，启用是开发人员的明确操作。本版不根据模型自评分自动晋升路线。

## 验证建议

先用内置流程分别从首页、通讯录、已有聊天页执行；再试运行复盘候选。比较真实成功率、错误指引数、滑动次数、模型调用和耗时。错误、取消和失败不从分母删除。保留微信版本和手机系统信息；界面变化后重新验证，必要时回退版本。
