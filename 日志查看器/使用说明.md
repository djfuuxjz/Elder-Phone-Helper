# 查看器界面更新

- 导入后采用固定窗口三栏布局，右侧截图完整适配可用区域，不需要上下滚动图片；左侧列表和中间日志各自滚动。
- “适应窗口”恢复完整截图，“放大查看”临时扩大图片面板，按 Escape 或“返回侧栏”退出。节点列表默认折叠，需要时展开。
- 左侧标题显示“第几步 · 具体动作”；建议、指引和自动派发的来源另行标注。没有动作记录时显示“观察页面”，不推测动作已完成。尝试次数和请求 ID 保留在中间详情。
- 中间“复制本步日志”包含本次请求的完整事件、模型内容、诊断、截图引用和 UI 树 JSON。复制文本不包含图片本身，给 AI 看图时需另附对应截图。复制权限被拒绝时会提供可手动复制的弹窗。

# V0.3.0 查看器新增功能

右侧可切换原始截图与 UI 节点叠加，按短编号查看节点。粉框为 UI 节点，橙框为模型/展示目标，蓝色虚线为选中节点。点击图片节点和右侧列表可互相定位。支持隐藏空容器、仅看可点击、搜索和缩放。

详细错误阶段、规则、期望与实际值在“过程与结果”中展示；操作事件来源不确定时不会标为确定用户操作。旧日志缺少的截图与采集统计无法补造。`0 debug` 已整理为项目最外层的 `02_真机测试日志`。

# 手机助手日志查看器

## 打开与导入

1. 用 Chrome 或 Edge 打开同目录的 **index.html**，不用启动服务、安装软件包或联网。
2. 点击“选择日志文件夹”，选择解压后的 `run_…` 文件夹。浏览器的文件选择确认只是允许页面读取所选本地文件，不会上传。
3. 也可以选择 `02_真机测试日志` 文件夹，一次导入多个运行；用“当前运行”切换。
4. 左边选一个步骤/尝试，中央看输入、输出、错误与事件，右边看对应截图。

“选择多个文件”用于同一次运行的 JSONL、JSON 和 JPG。不要将不同运行的同名附件混在这个模式中；多运行使用文件夹模式。ZIP 必须先解压。

## 查看方式

- 搜索完整 `request_id`，或 `_24_2`（第 24 步、第 2 次尝试），也能搜索错误文本。
- 筛选“被拒绝 / 出错”，查看模型建议未展示的具体原因。
- “模型输入”：实际发送的提示词、页面信息和上下文。
- “模型输出”：可读正文、完整 API 返回、App 解析结果。
- “UI Tree”：搜索节点文字、描述或 ID，点击节点在截图上显示坐标框。
- “过程与结果”：按原日志顺序串联同一次请求的准备、发送、返回、接受/拒绝；每条都有原 JSONL 行号。
- “查看整次运行事件”：包括没有 request_id 的观察、暂停、重试和停止。
- “打开原始截图”：单独查看完整图片。

橙框会注明是“实际展示目标”“模型建议目标”或“手动选择的节点”。看到模型目标框，不代表 App 已展示指引。没有截图时明确说明；截图和树比例不一致时不强行画框。

## 指标口径

实际调用只统计 `request`，不把 `request_prepared` 再算一次。实际展示只统计 `guidance`。耗时中位数包含记录了 latency_ms 的错误响应。STOPPED 表示停止，COMPLETED 是应用报告的状态，是否真实成功仍需人工确认。

每个 request_id 在所属运行内关联；只有 step/attempt 的事件仅在能够唯一确定时归入请求。附件按照日志所在目录和引用文件名解析，不跨运行寻找同名文件。坏行、缺少附件、重名和歧义均显示提醒，不会猜测对应关系。单个 JSONL 上限 30 MB，超出会明确报错。

## 数据与限制

纯本地静态工具，无远程脚本、字体、统计或网络请求。清空、关闭或刷新后需重新选择文件；不修改原始日志。分享工具时只需分享这个工具文件夹，不必附带私人日志。保留 HTML、JS 和 CSS 在同一文件夹。

## 开发验证

测试脚本统一在 tests/ 下。以下从日志查看器目录执行，需要 Node22：

```sh
node --test tests/test-geometry.cjs tests/test-ui.cjs
LOG_FIXTURE='/你的路径/run_1792305039224_bd125093/events.jsonl' node --test tests/test-core.cjs
node tests/test-integration.cjs
```

core 测试中的既有真实样本断言需要指定原样本，不要换成任意一次运行。当前浏览器集成使用 Mac 默认 Chrome 和 Node 内置 WebSocket，不需要 Playwright，也不读取用户浏览器资料；预览生成在临时目录，不再写入查看器文件夹。
