# 老年人手机助手 · Elder Phone Helper

一个帮助老年人操作手机的 Android 原型。当前仅支持固定任务：**在微信中给联系人“女儿”发起视频通话**。

助手读取当前页面，通过云端模型判断下一步，在屏幕上高亮目标并提供文字/语音提示。**微信中的点击、输入、滑动和返回由用户本人完成，App 不自动执行这些操作。** 启动任务时可以请求系统直接打开微信。

当前代码版本：**V0.1.5**（versionCode 6，Android 11+）。本仓库整理了 PRD、开发计划、当前源码、各版 APK/源码归档、开发与测试文档，以及离线日志查看器。历史归档是发布快照，不代表恢复了各版本的原始 Git 提交历史。

> 已有用户真机测试反馈，并据此多次迭代；本地测试通过不代表所有微信页面、手机系统和真实 API 均已验收。当前并未完成覆盖全部用例的真实成功率统计。猫咪＋气泡的温馨适老化界面目前仅形成设计要求，**尚未在 V0.1.5 实现**。

### 1. 准备手机

1. 使用 Android 11 或更新版本的手机；主要测试设备为小米 15，HyperOS/微信版本差异仍需验证。
2. 安装 APK；系统可能要求允许该来源安装应用。仓库中各次交付包沿用同一开发签名，可在兼容条件下覆盖升级。
3. 确认微信已登录、目标联系人可通过“女儿”搜索并能结合实际备注辨认；不要求联系人备注精确等于“女儿”。多个同名结果仍需模型和用户判断。
4. 测试会真实发起视频邀请，请与联系人约好测试，必要时自行挂断。

### 2. 配置助手

1. 打开“我的 → 无障碍设置”，启用“手机助手 · 操作引导”，返回 App 确认服务已连接。
2. 在“我的”填写模型 API 地址、模型名和自己的 API Key，保存配置。
3. 当前代码默认地址为 `https://api.deepseek.com`，默认模型字段为 `deepseek-flash`。这些是项目内默认值，实际可用模型与图片能力以你的服务账户为准。
4. 仅当所选模型/接口确实支持图片输入时开启“模型支持图片输入”。本项目使用兼容 Chat Completions 的 HTTPS 请求，不保证任意模型服务直接兼容。

密钥通过 Android Keystore 加密存储在手机上，不需要填写到源码或 GitHub；模型调用使用用户自己的服务额度。

### 3. 执行任务

1. 在“任务”页点击“给女儿打视频电话”，确认读屏与模型调用说明。
2. 助手请求系统打开微信，然后读取当前页面并给出下一步提示。
3. 按高亮、文字和语音亲自操作。引导栏可拖动，必要时点“重试”。
4. 返回操作优先定位页面返回按钮；模型只给出 `back` 而没有位置时，会要求补充定位，支持图片时补截图。无法找到按钮时才退回系统返回方法，不保证所有页面都能识别到按钮。
5. 点击“停止”会结束引导、移除浮层并返回助手。
6. 模型声明成功后，显示“任务已成功”1秒并关闭浮层，随后后台复盘。当前 App 不再用固定页面词语二次校验完成，因此模型误判成功时 App 也会结束。

## 当前能力与边界

| 能力 | 当前行为 |
|---|---|
| 页面观察 | AccessibilityService 读取 UI Tree；必要时截图；页面变化后重新观察 |
| 模型调用 | 云端 API，携带当前页面、当前流程和本次步骤摘要；请求发送至少间隔1秒 |
| 引导 | 点击/输入/返回目标高亮、文字与 TTS；不自动操作微信 |
| 结果有效性 | 检查输出结构、坐标、节点和过期响应；已移除输入/搜索/加号业务拦截与固定姓名/置信度门槛 |
| 路线约束 | 优先搜索、少滑动；启用流程时仍保留联系人检索阶段的滑动限制 |
| 完成 | 模型返回 `complete` + `task_completed=true` 后结束，展示成功1秒 |
| 流程学习 | 成功后 AI 复盘，保存较短路线的新版本并默认自动启用；支持人工维护和回退 |
| Debug | 本机输入输出、UI Tree/截图引用、step/attempt/request_id、耗时、取消与错误、导出和验收标注 |
| 未实现 | 自定义语音任务、ASR、登录、用户历史记录、多任务入口、自动点击、支付业务 |

## 流程库如何使用

入口：“我的 → 流程库 · 开发维护”。

流程库保存语义步骤，不保存固定屏幕坐标，也不训练模型。每次请求向模型提供**当前启用流程＋当前页面＋本次步骤摘要**，模型据此决定下一步，并按实际起点跳过已完成步骤。

默认参考路线为：搜索联系人 → 进入目标聊天页 → 输入栏旁加号 → 音视频通话 → 视频通话 → 判断完成。

- 成功后模型结合已记录过程去掉重复、错误与绕路，新流程保存并供下次使用；它是基于本次记录的较短路线，不是经数学证明的全局最短路线。
- 旧版本、来源运行和复盘理由保留，支持查看、新建、粘贴 JSON 导入、导出、编辑、试运行、启用和回退。
- 当前版本被人工锁定、流程被停用或任务期间切换版本时，复盘只保存，不覆盖当前选择；试运行与默认启用版本不同也不会自动替换默认版。
- 复盘是额外的 API 调用。失败不会撤销已完成状态；新任务/服务关闭会取消未完成复盘。需要完整日志时等待复盘结束再导出。

见 [流程库方案与历次变更](docs/WORKFLOW_LIBRARY.md)，最新行为以 [V0.1.4](docs/RELEASE_0.1.4.md) 和 [V0.1.5](docs/RELEASE_0.1.5.md) 为准。

## 调试和查看日志

1. 在“我的 → Debug · 开发日志”选择运行，可查看模型请求、响应、UI Tree、截图和统计。
2. 任务与复盘结束后导出 ZIP；名称含手机本地日期时间，例如 `debug_yyyyMMdd_HHmmss_SSS_编号.zip`。
3. 在电脑解压调试包和日志查看器，用浏览器打开 `日志查看器/index.html`，导入包含 `events.jsonl` 及附件的完整文件夹。
4. 按 `step`、`attempt`、`request_id` 对照输入输出、截图和实际展示结果。查看器离线使用，不上传日志。
5. “已展示”不代表用户已完成点击；“已丢弃”可能是页面变化或用户停止；成功后复盘有独立请求及启用状态。

真实运行日志可能包含联系人、聊天内容和截图，因此未上传到本仓库。调试记录不是用户历史记录功能。

## 从源码构建

准备 JDK 17、Android SDK Platform 35、Build Tools 35.0.0。工程固定 Gradle 8.11.1、AGP 8.9.2、Kotlin 2.1.20。Android Studio 可直接打开项目。

配置 `ANDROID_HOME`，或在本机创建不提交的 `local.properties`，填写 `sdk.dir=你的SDK绝对路径`，然后运行：

```sh
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

Windows 使用 `gradlew.bat`。首次构建需要联网下载依赖。APK 输出：`app/build/outputs/apk/debug/app-debug.apk`。

`tools/build-local.sh` 专供原开发机已准备好的 `.toolchain/` 使用；仓库不附带该工具链，新电脑请使用标准 Gradle Wrapper。

自行构建的调试签名通常与仓库发布包不同，可能无法覆盖安装。不要删除数据后才备份：先导出需要保留的调试资料，再处理签名不同的安装问题。

## 数据和资料管理

读屏文字与必要截图会发给你配置的模型服务，本机保存调试资料；不提供独立云端日志服务器。任务停止后停止读屏，成功后的复盘仅使用已保存过程。

本仓库不包含API密钥、签名私钥、手机私有数据、真实聊天日志、工具链及构建缓存。第三方参考APK不作为本项目代码或交付包上传。设计参考图仅用于内部风格参考；未在本次整理中新增开源许可或声称拥有第三方素材权利。
